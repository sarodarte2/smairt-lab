# SMAIRT AI Skill Usage

The skills under `src/smairt/assets/skills/` are SMAIRT-owned procedures for
coding assistants: thin instructions that call the `smairt` CLI to do the
mechanics, never copied into generated projects. They ship as package data
inside `smairt` itself (alongside `assets/scaffold-blueprint.yaml`) and are
resolved from an installed package by `smairt.skills`, never by a path
relative to the repo checkout. The project-level contract — the two unit
kinds, frontmatter duties, evidence rules, and the stakes/explanation rules —
lives in each project's own `AGENTS.md`, generated by `smairt new`. Skills
reference that contract; they don't restate it.

## Available Skills

- `smairt-new-project` — interview a researcher and scaffold a new
  project, fully-flagged.
- `smairt-orient` — join or resume a session from derived state.
- `smairt-new-question` — start an exploratory probe.
- `smairt-new-stage` — add a step to the spine.
- `smairt-close-question` — record what happened, what it means,
  and a verdict.
- `smairt-fork` — record alternatives, contained or propagating.
- `smairt-adopt` — walk a pre-existing project's folders after
  `smairt adopt` and propose reference units, one approval at a time.
- `smairt-adversarial-review` — researcher-invoked, argues against
  the current interpretation from the units' own evidence.

Each is a folder containing a single `SKILL.md`; `smairt.skills.list_skills()`
lists the names above and `smairt.skills.read_skill(name)` returns one's text.

## Use

Install SMAIRT and create the project first:

```bash
uv tool install .
smairt new
```

Then make the skills available to an assistant that supports skills (all
SMAIRT-supported harnesses are assumed to) — `smairt connect` is the intended
delivery path once it wires skills in alongside the hooks it already writes.
Until then, `smairt.skills.read_skill(name)` (or the `SKILL.md` files under
`src/smairt/assets/skills/` in a checkout) is how to reach the text directly.
The assistant should read the project's own `AGENTS.md` and `STATUS.md`, and
follow whichever skill matches the task at hand — never reconstruct project
state from conversation memory alone.

Skills do not create projects, replace the CLI, or validate scientific
claims; the researcher owns novelty, judgment, and conclusions.
